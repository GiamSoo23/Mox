# Mox protocol, v2

The contract between every Mox client (macOS, Android, Windows, iPhone
Shortcuts) and the backend. Clients talk to Supabase directly over HTTPS.
There's no Mox server, so this document **is** the API.

- Schema: [backend/supabase/migrations/](../backend/supabase/migrations/)
- Design and reasoning: [docs/DESIGN.md §8](../docs/DESIGN.md)
- Test data every client must pass: [fixtures/](fixtures/)

Status: **v2, not yet used by the apps.** They still speak v1 until #11 and
#12 land.

---

## 1. What a client stores

Obtained once, from the pairing QR (#14) or the setup wizard (#22):

| Value | Example | Secret? |
|---|---|---|
| Project URL | `https://abcd1234.supabase.co` | no |
| Publishable key | `sb_publishable_…` | low: identifies the project, grants nothing on its own |
| Mox user email | `mox-7f3a…@mox.invalid` | yes |
| Mox user password | 32+ random characters | **yes**: Keychain / Android Keystore / Windows credential store |
| Device id | a UUID, generated by the client at pairing | no |

The device id never changes for an installation. The client puts it in
every row it writes, and uses it to recognize (and skip) its own uploads.

## 2. Signing in

Every device signs in as the same Mox user and keeps **its own session**.
Never share a refresh token between devices: Supabase rotates it on every
use.

**Sign in**

```http
POST {url}/auth/v1/token?grant_type=password
apikey: {publishable key}
Content-Type: application/json

{"email": "{email}", "password": "{password}"}
```

The response has `access_token` (a JWT, valid for `expires_in` seconds),
`refresh_token` and `user.id`.

**Refresh** (shortly before `expires_at`, or after a `401`):

```http
POST {url}/auth/v1/token?grant_type=refresh_token
apikey: {publishable key}
Content-Type: application/json

{"refresh_token": "{refresh token}"}
```

If refreshing fails, sign in again with the stored password.

## 3. Headers used on every call below

| Header | Value |
|---|---|
| `apikey` | publishable key |
| `Authorization` | `Bearer {access token}` |
| `Accept-Profile` | `mox` (reads: GET) |
| `Content-Profile` | `mox` (writes: POST, PATCH) |

The profile headers tell PostgREST to use the `mox` schema instead of
`public`. Storage calls don't need them.

## 4. Calls

### 4.1 Check the schema version (on start, after sign-in)

```http
GET {url}/rest/v1/meta?select=schema_version
Accept-Profile: mox
```

`[{"schema_version": 2}]`. If the version isn't **2**, stop and tell the
user that the backend and the app don't match. An empty array means this
user isn't the owner (see §7).

### 4.2 Read the slot (poll every 5 s)

```http
GET {url}/rest/v1/current_file?id=eq.1&select=*
Accept-Profile: mox
```

`[]` means nothing has been sent yet. Otherwise it returns one row (§5).

### 4.3 Upload the bytes (step 1 of sending)

```http
POST {url}/storage/v1/object/mox/current
Content-Type: {mime type, or application/octet-stream}
x-upsert: true

<file bytes, streamed. A bundle (#18) is the zip's bytes>
```

The object is **always** named `current`, whatever the file's name or
extension.

### 4.4 Replace the row (step 2 of sending, only after 4.3 succeeds)

```http
POST {url}/rest/v1/current_file?on_conflict=id
Content-Profile: mox
Content-Type: application/json
Prefer: resolution=merge-duplicates,return=representation

{
  "id": 1,
  "original_name": "IMG_0001.jpg",
  "mime_type": "image/jpeg",
  "size_bytes": 2048,
  "kind": "file",
  "item_count": 1,
  "source_platform": "macos",
  "source_device_id": "{device id}"
}
```

Don't send `uploaded_at`: the database sets it on every replace (#48). The
response is the stored row, as a one-element array.

Order matters: bytes first, row second. Other devices only act when the row
changes, so they never see a row that points at bytes that aren't there yet.

### 4.5 Get a download link

```http
POST {url}/storage/v1/object/sign/mox/current
Content-Type: application/json

{"expiresIn": 600}
```

`{"signedURL": "/object/sign/mox/current?token=…"}`. It's relative:
prefix it with `{url}/storage/v1`.

### 4.6 Download

`GET` the full signed URL, with no auth headers. Stream it to disk. Use
`original_name` for the file name (deduplicated: `name (1).ext`).

## 5. The row

| Field | Type | Rule | Set by |
|---|---|---|---|
| `id` | int | always `1` | client |
| `original_name` | string | 1–255 characters | client |
| `mime_type` | string or `null` | | client |
| `size_bytes` | int | 1 – 52 428 800 (50 MB) | client |
| `kind` | string | `file` or `bundle` | client |
| `item_count` | int | `1` for a file, `2`+ for a bundle | client |
| `source_platform` | string | `macos`, `windows`, `android` or `ios` | client |
| `source_device_id` | UUID string | required | client |
| `uploaded_at` | ISO 8601 timestamp | | **database** |

The database enforces every rule in this table. A client should still check
them before uploading, so it can explain the problem instead of showing a
server error.

**Forward compatibility:** ignore fields you don't recognize. Newer schema
versions may add columns without bumping the major version.

## 6. Client behavior

**Sending:** check the size (≤ 50 MB) and the name, then do 4.3, then 4.4.
If 4.3 fails, don't touch the row.

**Receiving:** on every poll (4.2), act on the row only if all of these hold:

1. `source_device_id` isn't this device's id,
2. `uploaded_at` differs from the last one this device handled (persisted
   across restarts),
3. the row passes the rules in §5. If it doesn't, show an error.

Then 4.5 → 4.6, and save it where the platform expects (Android: photos and
videos to the Camera folder, #43). If `kind` is `bundle`, unpack it (#18).
**Never unpack a `file`, even if it's a `.zip`.**

On the first poll after launch, update the UI but don't notify for a file
that was already handled.

## 7. Errors

| Symptom | Meaning | What the client does |
|---|---|---|
| `401` | access token expired | refresh (§2), retry once |
| `400` from `/auth/v1/token` | wrong email or password | ask to pair again |
| `406`/`PGRST106` "schema must be one of…" | `mox` isn't in the project's exposed schemas | tell the user to add it (backend/README.md) |
| `42501` / `403`, or `meta` returns `[]` | signed in, but not the owner | tell the user `mox.meta.owner_id` isn't set to this user |
| `413`, or storage "Payload too large" | over the bucket's limit | should have been caught by the size check |
| network error | — | keep the last good state, retry on the next poll |
